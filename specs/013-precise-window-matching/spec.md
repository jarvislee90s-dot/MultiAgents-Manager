# 功能规格说明：精准窗口匹配（认领池 + UIA 正文 + marker 新通道）

**功能分支**：`013-precise-window-matching`

**创建日期**：2026-08-25

**状态**：草稿

**输入**：用户实测反馈与实机取证——① codex/opencode 跳转的候选列表全量展示（含 claude 窗口），根因是三个工具向终端标题暴露自身信息的程度不同（claude 写 "✳ Claude Code"、opencode 写缩写 "OC | …"、codex 不写标题），打分全零时按设计回退全量，"他工具已认领"的窗口未被排除；② 双 claude 窗口标题逐字相同且 marker 为死层（hook 触发正常但 `/dev/tty` 在"claude.exe 原生进程 spawn 的 bash"上下文不可达，实测全屏无 MAM: 标题）；③ 卡片四标签（工具名/项目名/卡片标签/session hash）在窗口侧仅有标题一个暴露面。

## 用户场景与测试

### 用户故事 1 — 候选列表永不出现他工具窗口（优先级: P1）

**验收场景**：

1. **给定** 两个终端跑 claude、一个跑 opencode、一个空 PowerShell，**当** 点击 codex 会话卡片进入选择器，**则** 候选列表不含两个 Claude Code 窗口（被 claude 认领排除），只含未被认领的终端
2. **给定** 同上环境，**当** 点击 claude 卡片进入选择器，**则** 候选列表不含 "OC | …" 窗口（被 opencode 认领排除）
3. **给定** 某窗口标题同时含两个工具关键词（罕见），**则** 视为中立不排除，交由上层消歧

### 用户故事 2 — 双同款会话精确跳转（优先级: P1）

**验收场景**：

1. **给定** 两个终端分别跑同款工具的会话（如双 claude），**当** 点击其中一张卡片，**则** 精确聚焦对应窗口，不弹选择器——命中来源按优先级：标题 `MAM:<8 位>`（marker）或 终端可见正文与卡片最新消息尾部匹配（UIA）
2. **给定** marker 与 UIA 均未命中（如最新消息已滚出屏幕），**当** 点击卡片，**则** 走认领排除 + 标题打分，仍歧义时弹选择器（列表已按用户故事 1 排除无关窗口）

### 用户故事 3 — marker 通道修复或明确退役（优先级: P2）

**验收场景**：

1. **给定** hook 触发（会话事件正常产出），**当** 实施完成后，**则** 要么交互终端标题实测出现 `MAM:<8 位>` 且与卡片前缀对读（通道修复成功），要么 spec 记录 CONOUT$ 通道亦不可达的实测结论、marker 层退役且 UIA 升为精确匹配主力（二选一，结论可追溯）

## 设计

### 1. 窗口池认领模型（Ambiguous 候选生成重构）

- **认领关键词映射**（集中定义）：`claude → ["claude"]`、`codex → ["codex"]`、`opencode → ["opencode", "OC |"]`、`openclaw → ["openclaw"]`；标题（不区分大小写）命中某工具任一关键词 → 该窗口被该工具认领
- **候选规则**：工具 X 的候选 = X 认领的窗口 ∪ 未被任何工具认领的中立窗口（PowerShell/cmd 等）；**其他工具认领的窗口无条件排除**；排序为先 X 认领、后中立（沿用现有打分值降序）
- 作用点：`resolve_and_focus` 的 Ambiguous 分支（与标题打分共用同一份候选集）

### 2. UIA 正文匹配（新增精确层，位于 marker 之后、标题打分之前）

- **触发条件**：仅当近祖定位到多窗口宿主（WT 场景）且 marker 未命中时，对候选窗口逐个执行；候选上限 8 个
- **机制**：Windows UI Automation（`windows` crate 增加 `Win32_UI_Accessibility` feature）获取窗口终端控件（TextPattern）的可见文本；与 `Session.lastMessage` 尾部约 40 字符做匹配（两侧空白归一化——连续空白/换行压为单空格；参照文本复用看板现有提取结果，不另建提取逻辑）
- **约束**：单窗口读取超时 200ms，总预算 800ms；COM 初始化或模式获取失败视为该窗口 miss；全部 miss 静默降级到下一层（不报错不弹窗）
- **时机有利性**：点击跳转通常发生在任务刚结束（通知弹出后），最终回复仍在屏幕视口内，命中率高；消息滚出屏幕为已知 miss 场景，由选择器兜底

### 3. marker 通道换 CONOUT$（spike 先行，结论可退）

- **问题**：现 `/dev/tty` 写入要求 MSYS 伪终端，hook 的 bash（由 claude.exe 原生 spawn）不具备 → 永远失败
- **候选载体**：hook 脚本内改写 Windows 控制台输出设备 `CONOUT$`——优先尝试 PowerShell 单行（`[IO.File]::WriteAllText('CONOUT$', <OSC 序列>)`，hook 子进程继承宿主控制台，理论可达）；若实测性能/覆盖不可接受，备选 MAM 附带轻量 marker helper 可执行文件。实施时 spike 验证两点：标题实测出现 marker；claude 自身标题重写的覆盖竞争下 marker 存活窗口是否覆盖"任务结束→用户点击"时段
- **go/no-go**：不成立则 marker 层代码保留禁用、spike 结论文档化（沿用既有 spike 记录惯例），UIA 为精确匹配主力

### 4. 降级链（更新后）

近祖优先 + shell 黑名单 → ② marker 标题精确（视 spike）→ ③ UIA 正文匹配 → ④ 认领排除 + 标题打分 → ⑤ 选择器（永远正确）

- 纯函数单测：认领判定与候选过滤（关键词命中/多认领中立/排除规则）；正文尾段归一化匹配函数
- spike 报告：CONOUT$ 通道结论（手动实测 + 记录）
- 人工验证：用户故事 1-3 全部场景；核心矩阵 = 双 claude + 单 opencode + 单空 PowerShell + codex 会话，四张卡片逐一验证候选列表与跳转结果
