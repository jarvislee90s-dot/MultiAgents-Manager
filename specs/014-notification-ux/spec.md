# 功能规格说明：通知浮窗体验（动态高度 + 渠道统一 + 通知历史）

**功能分支**：`014-notification-ux`

**创建日期**：2026-08-25

**状态**：草稿

**输入**：用户实测反馈与决策——① 候选弹窗窗口固定 360×110（`notification.rs:21-22` 常量，无任何 set_size 逻辑），候选多于两条即被截断无法点选；② "使用系统通知"开关的实际价值仅剩系统通知中心历史（失败降级路径不依赖开关、几乎不触发），用户决策砍掉开关、以应用内历史列表替代；③ 需要通知历史回溯能力。

## 用户场景与测试

### 用户故事 1 — 候选弹窗完整可点（优先级: P1）

**验收场景**：

1. **给定** 通知浮窗弹出候选列表（≥3 个窗口），**当** 查看，**则** 全部候选完整可见可点击，无截断
2. **给定** 候选数量很多（如 8 个），**当** 列表超出最大高度（约 400px），**则** 窗口达到最大高度后列表内部滚动，仍可点选所有项
3. **给定** 候选被处理（点选或新通知到达清空），**当** 回到通知卡片形态，**则** 窗口高度还原为默认（110px）

### 用户故事 2 — 通知渠道统一为应用内浮窗（优先级: P2）

**验收场景**：

1. **给定** 设置页，**当** 查看，**则** "使用系统通知"开关不存在；通知一律走应用内浮窗
2. **给定** 设置页通知测试按钮，**当** 点击，**则** 触发一次应用内浮窗预览（含假会话数据的完整浮窗形态），而非系统 toast
3. **给定** 浮窗创建失败的极端场景，**当** 降级发生，**则** 仍自动走系统 toast（降级路径与开关解耦，保留不删）
4. **给定** 旧版本用户的 `mam.useSystemNotification` localStorage 键，**则** 读取时忽略并清理，不报错

### 用户故事 3 — 通知历史可回溯（优先级: P1）

**验收场景**：

1. **给定** 若干通知已弹出（含已自动消失的），**当** 点击首页头部铃铛图标，**则** 弹出历史面板，按时间倒序展示最近 50 条：工具徽标（图标+工具色）、项目名、终态标签、相对时间、最新消息预览
2. **给定** 有新通知到达且历史面板未打开，**当** 查看铃铛，**则** 显示未读计数角标；打开面板后计数清零
3. **给定** 历史面板中某条记录对应的会话仍在运行，**当** 点击该条，**则** 执行与卡片一致的跳转（复用 `useSessionJump`）；会话已结束时点击提示不可跳转（toast），不崩溃
4. **给定** 中英文界面，**则** 铃铛提示、面板文案、时间格式跟随 i18n（键集对齐）
5. **给定** 应用重启，**当** 打开历史面板，**则** 历史仍在（持久化），上限 50 条自动淘汰最旧

## 设计

### 1. 候选弹窗动态高度

- 通知窗口高度由前端驱动：显示候选时按 `高度 = min(60 + N × 34 + 16, 400)` 计算并 `getCurrentWindow().setSize(new LogicalSize(360, h))`；候选清空/新通知到达时还原 110
- `capabilities/notification.json` 追加 `core:window:allow-set-size` 权限
- 候选项文本保持单行截断（title 属性已有完整标题）

### 2. 渠道统一与清理

- 删除设置页"使用系统通知"开关及 `useNotification` 中的分支（浮窗路径成为唯一主通道）；`mam.useSystemNotification` 键随 `getSoundConfig` 同类方式读取清理
- **失败降级路径保留**（`invoke` catch → `sendNotification`，不依赖开关）；系统通知插件依赖与权限申请保留
- 设置页原"桌面通知测试"按钮改为"测试浮窗"：以固定假数据（claude · 通知测试 · 等待操作 · 示例消息）调用 `show_notification_window`，直接验证浮窗全链路

### 3. 通知历史

- **记录**：每次通知触发时（与浮窗/降级发送同点）写入 `localStorage: mam-notification-history`（数组，最新在前，容量 50 自动裁剪）；记录字段：`agentType、projectName、status（终态枚举）、lastMessage、pid、sessionId、at（时间戳）、read` 的新记录未读
- **入口**：首页头部新增铃铛图标（lucide `Bell`）+ 未读数角标（未读 = `read === false` 计数）；点击展开历史面板（Popover/内联面板，沿用项目现有 UI 组件风格），打开时将全部标记已读
- **面板条目**：复用 `agentBadge` 的图标与工具色渲染工具徽标；相对时间复用 SessionCard 的时间格式化逻辑（必要时抽公共函数）；点击条目调 `useSessionJump().focus`（会话可能已结束——`pid` 失效时后端返回"未找到可聚焦的窗口"，前端 toast 呈现即为验收 3 的行为）
- **不做**：历史条目的删除/搜索/筛选、历史持久化到 SQLite（localStorage 容量足够且免迁移）

## 范围外

- 系统通知中心历史、勿扰时段、多显示器分发
- 历史条目管理（删除/标星等）
- 300ms ready-ack 竞态修复（延续既往后续债清单，另行排期）

## 测试策略

- 纯逻辑单测（如可行）：历史记录裁剪与未读计数函数
- `pnpm check`（含 check:i18n 键对齐）
- 人工验证：三个用户故事全部场景；重点为"≥3 候选完整可点 + 还原"与"消失的通知可在历史中找回并跳转"
