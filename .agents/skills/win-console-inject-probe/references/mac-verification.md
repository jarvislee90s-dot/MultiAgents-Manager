# macOS 侧验证清单（新工具接入流水线第二段）

> 定位：新工具在 Windows 用本技能定族规格后，macOS 只做**轻量差异验证**（20–30 分钟）——不做重型探测。macOS 三通道是官方 API，"能不能注入"基本不成问题，要验的只是族/工具特异行为与环境项。

## 环境准备（首次）

1. `brew install --cask iterm2 && brew install tmux`（如缺；测试前置，可逆）。
2. **TCC 自动化授权**：MAM（尤其开发版）首次控制 Terminal/iTerm2 需在「系统设置 > 隐私与安全性 > 自动化」允许；被拒时 osascript 报 -1743——resume/注入回执已按此分类（M2 修复），按指引授权后重试。
3. **iTerm2 3.7.2 + macOS 26 已知脆弱点**（2026-09-20 复验证实并升级）：`create window … with command "…"` **恒产 0-tab 死窗**（100% 复现，osascript 假成功 exit 0/stderr 空——「延迟物化」证伪，是硬断）——resume/开窗类操作勿依赖该形态，**出手后必须效果回查**；AppleScript 冷启动首次调用必 -1712 超时（60–120s），**超时后引擎自愈、无需重启 iTerm2**，热态仍可能数十秒——健康探测按「超时计数 + 短退避重试」设计，勿按「卡死即判死」。
4. **resume 开窗通道顺序**：本机实测 Terminal.app `do script` 全通、iTerm2 带命令 create 恒死窗——macOS 上 Terminal 优先、iTerm2 次选 + 效果回查兜底。

## 四点验证清单

1. **短消息送达+确认回执**：tmux 通道必测 + iTerm2/Terminal 至少一条 GUI 通道；断言「已送达」回执 + 终端可见 + agent 回复。
2. **长消息（2000 字）**：快消费者即时、慢消费者（opencode 类）预算内 delivered；超预期则记族档案。
3. **族特异行为——回车提交**：注入短消息后观察是否自动提交；**对照 `known-families.md` 平台差异表的该工具基线**——被吞 → 确认 M3B 家族感知文案生效 + 登记该工具 macOS 行为；新工具无基线 → 实测入档（这正是本清单的存在意义）。
4. **审批可达性**：触发一次审批 → 红卡可用性（当前 macOS 红卡暂不可达，M1A 钩子通道为后续批次）→ 降级路径验证：普通发送键位字符（如 "1"/"y"）→ 排队/投递 → 审批被正确应答、409 守卫不发错误键位。

## 纪律与产出

- 不碰用户会话；测试一律临时项目目录（如 `/tmp/mam-verify-<tool>`）；结束清进程清痕迹。
- 差异登记两处：`known-families.md` 平台差异表（族级）+ 工具档案（工具级，含版本号）。
- 版本漂移顺带记录（实测版本 vs 档案版本，键位/marker 是否变化）。
