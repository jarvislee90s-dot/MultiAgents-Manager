# ✨ v0.4.0 更新 — ZCode 第七工具 + 跳转直达 + codex 技能目录私有化 + 会话监控大修

本版本五大主题：**ZCode（智谱）接入**、**同项目双开终端跳转直达**、**跳转 marker 通道与消歧安全门**、**codex 技能目录私有化（跨工具不再互相干扰）**、**会话监控性能与准确性大修**（轮询卡死修复、新版 Codex 桌面端适配、状态灯语义修正）。

---

## 🟣 ZCode 第七工具支持

智谱桌面 AI 编程助手（Electron APP 形态）全链路接入：

- **会话看板**：双 SQLite 会话聚合（任务索引 + 消息流），每会话一卡、24h 窗口、归档/删除过滤；状态从消息流尾部按序倒扫推导，子代理长任务经「后代活跃度仲裁」保持运行中（主会话静默 + 子代理活跃 = 健康等待）
- **跳转 = 直接聚焦唯一窗口**：ZCode 为单窗口应用，点击卡片零歧义锁定
- **资源管理**：skill 分发到 `~/.zcode/skills/`（实机验证被识别）+ MCP 配置读-改-写（仅动 `mcp.servers` 子树，原键序保留，`enable:false` 条目如实显示停用态）

> 设计说明：ZCode 的工作区深链（`zcode://workspace/open`）经实机验收后有意不接入——它的落点是"新会话编辑器"而非已有会话，且每次派发都会弹信任确认。跳转改为窗口聚焦后，点击即达。

## 🎯 同项目双开跳转直达

Kimi / OpenCode 在同一项目开两个终端时，点击卡片**不再弹选择器**——终端窗口标题与会话标题归一化比对（剥 spinner / 工具前缀 / 省略号），唯一命中即锁定。会话标题经看板 / 通知 / 桌宠 / 历史全部入口统一透传。

---

## 🏷️ 跳转 marker 通道 + 消歧安全门（Windows）

窗口定位从「启发式猜」升级为「正向证据证」，并给猜不了的情况上了安全门：

- **一次性身份标记**：跳转判定前对目标终端标题贴 ` — MAM:<会话 id 前 12 位>`，消歧层按标记精确命中；**聚焦成功后自动清除**，标题回到干净态
- **防叠加**：不同会话先后跳转同一窗口，贴新前先剥旧——不会出现双标记残留
- **安全门**：同项目双开等卡片↔终端配对存疑的场景，自动禁用猜测式锁定与标记注入——**宁可弹选择器让你挑，绝不静默锁错窗**；此类卡片有「同项目双开」提示角标
- **零依赖可用**：helper（`mam-marker`）随应用自动分发到 `~/.mam/bin/`，缺失或失败时全链静默回落既有消歧层，行为与旧版一致
- **claude Stop 宽限恢复**：hook 事件通道重构（事件文件以 session_id 分键 + 字符白名单防路径注入），claude 答完任务不再闪误报红灯

## 📦 codex 技能目录私有化 + `.agents` 共享目录只读化

- codex 的技能激活目录从跨工具共享的 `~/.agents/skills/` 切换为私有 `~/.codex/skills/`——**对 codex 单独启用/禁用技能不再影响 zcode 等其他工具**
- `~/.agents/skills/` 转为只读共享导入源：手装技能照常自动入库，但 MAM 不再向其写入，共享目录回归纯净
- 存量用户首次启动弹出**一次性迁移对话框**：「迁移到 `.codex/skills`」（启停状态无损）或「保留为共享」（脱钩 codex 启停、继续服务未适配工具），两种选择后不再打扰
- **SSOT 删除保护**：删除仍被共享目录引用的技能时先确认，防止未适配工具静默失效

## 🔧 会话监控性能与准确性大修

- **轮询卡死修复（会话扫描三层预算）**：会话历史堆积后（实机 codex 2GB / 388 文件）3 秒轮询曾把 CPU 打满、界面卡死。现零进程零解析、未变更文件缓存复用、无界历史扫描限 24h 窗口——重负载场景每轮解析量从数百文件降到零/个位数。架构契约写入 AGENTS.md，新工具接入自动受保护
- **新版 Codex 桌面端适配**：Codex APP 已把会话存储迁入 SQLite（rollout 文件不再更新），看板因此检测不到 APP 对话。现直接读取 `state_*.sqlite` / `thread_history_*.sqlite` 双库——实时元数据 + 内容投影可用则用 + turn 生命周期强信号 + 子代理树后代仲裁；CLI 前端继续走 rollout 双源并存
- **状态灯语义修正（停更不落兜底红灯）**：无内容信号时无法区分「等用户输入」与「对话已结束」，时间兜底一律落**绿灯（完成待看）**并接入未读/绿卡管线；红灯只保留给有证据的等待（内容判定、子代理仲裁「疑似卡住」）——聊完的会话不再顶着误导性的「等待操作」红灯

### 其他修复（节选）

- **空壳终端窗口不再混入选择器**：`C:\WINDOWS\system32\cmd.exe `（全路径 + 尾空格）形态的空闲终端按 basename 归一化识别排除（#47）
- **同标题双开的 UIA 仲裁**：两个窗口标题完全相同时，用会话正文尾串在窗口内容里仲裁，唯中者锁定、不唯一落选择器——宁弹不锁错（#49）
- **系统通知跳转补齐 title 透传**：从通知点进来的跳转同样享受标题匹配层（#45）
- **聚焦失败诚实报错**：系统拒绝置前（锁屏 / 前台锁）时显式 toast 提示，不再静默假成功
- **选择器零分候选视觉弱化**：无评分依据的候选降为 60% 不透明度，排序不变、不误杀真目标
- **窄卡标题尾巴阈值校准**：容器查询按内容盒度量，收窄时整段隐藏、不留孤立省略号（#51）
- **ZCode 集成加固**：宿主判定加路径门控与后代进程黑名单；缺排序列的会话整卡跳过（不出错误卡）；`enable:false` 的 MCP 条目导入保留并显示「源已停用」角标（#52）
- **claude hook 注册修复**：无空格路径去引号 + 正斜杠形态，SessionStart 不再报错
- **Kimi 双开跳转必弹选择器**：`state.json` 的 `updatedAt` 整数毫秒类型不匹配导致标题解析失败——现兼容数值/字符串双形态
- **OpenCode 同目录双终端只显示一个会话**：现按目录配对到各自进程
- Codex 会话标题前缀 8 → 12 位，消除同分钟创建会话的键碰撞
- 窗口标题匹配层空标题守卫（空串是任何键的「前缀」，会假命中）
- 深链派发改 ShellExecuteW 优先（`cmd /C start` 会破坏 percent-encoded URL）
