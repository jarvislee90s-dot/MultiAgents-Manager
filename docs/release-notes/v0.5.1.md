# 🔧 v0.5.1 更新 — 应用内更新器大成 + 外部域名向导 Windows 收口

本版本两大主题：**应用内更新器重做**（prerelease 渠道 + 忽略本版本 + 标题栏升级徽标）、
**外部域名（免域名）向导的 Windows 实测收口**（CLI 自定义路径查找治本 + 登录步修复 + 一轮架构评审全部收口）。

v0.5.1 不含数据库迁移与安全行为变更，从 v0.5.0 直接升级即可；应用内「设置 → 关于 → 检查更新」可自动升级。

---

## ⬆️ 应用内更新器重做

- **升级检查支持 prerelease 渠道**：改走 GitHub Releases API 按 semver 挑最大（含 prerelease）——
  旧 `releases/latest` 静态端点永远跳过预发布版，beta 版本推不出去
- **升级弹窗三按钮**：立即升级 / **忽略本版本**（持久记住，此后该版本不再自动弹）/ 稍后；
  release body 以 markdown 渲染（限高内滚）+ 预发布角标 + 具体 tag 页外链
- **标题栏升级徽标**（设置齿轮左侧）：无更新不渲染；被忽略的版本仍常显，想升随时能找到入口
- **失败原因第一眼可定位**：检查失败 toast 带具体原因（弱网 / 代理 / hosts 屏蔽），不再只进
  console；安装失败 toast 可操作反馈
- **Windows 升级不留下半截状态**：升级安装前走共享退出清理（隧道 / Tailscale / 电源锁不孤儿化）；
  启动时清扫 `%TEMP%` 升级残留
- **修掉一个「应用内升级恒失败」的隐患**：`TAURI_SIGNING_PRIVATE_KEY` 运行时注册门移除
  （私钥本就只在构建期需要，保留该门会让终端用户机器上的应用内升级必失败）

## 🛰 外部域名（免域名）向导 · Windows 实测收口

依据：2026-10-07 用户在本机 Windows 上**卸载 Tailscale 后从零端到端走完向导全程**
（下载 → 安装 → 登录 → 关 shields-up → 开通 Funnel → 可达性校验），全程正常。
实测暴露的缺口在本版本全部修掉：

- **Tailscale CLI 查找治本**：Windows MSI 允许自选安装路径，此前 MAM 只在默认目录找 CLI——
  装到自定义路径（尤其中文路径）会被误判「未安装」，向导反复下载安装。现补**服务注册表
  `ImagePath` 第二来源**（与盘符 / 目录名 / 中文无关；默认命中连注册表都不读），全落空如实
  报「未安装」，绝不返回猜的路径
- **登录步不再无可点之物**：此前 MAM 从不发起登录、授权链接永远为空，登录那一步没有任何
  可点的东西。现 MAM 主动发起 `tailscale login` 并把授权链接做成按钮——**合规红线一字不让：
  只递链接，不代登录、不持凭据**；登录窗口内窗口重新聚焦时自动重探一次（不做定时轮询）
- **自定义安装路径的事前提示**：动作文案点明「安装向导会让你选安装路径，用默认路径最省事；
  装到别处也可以，请记住那个路径」，前端常驻弱提示 MAM 的两个查找位置与「装完点刷新状态」
  （macOS 的 .pkg 固定装到 /Applications，不套用该文案）
- **撤下 Windows「未实机校验」黄标**：实测覆盖起点前移到第一步；诚实标注机制全保留——
  将来又出现未实测段落时黄标可原样回位
- **下载/安装步给「在走动」的不确定进度反馈**（不给假百分比）；**向导页脚新增解释
  Tailscale 是什么 + 官网外链**
- **卡名收成 4 字「外部域名」**：四列卡位放不下 9 字旧名（被截成「外部域名（免…」），
  「免域名」语义由卡面备注承载；标题悬停可见全名

## 🔒 评审收口（不变更用户可见行为）

- **login 单飞槽一锁到底（TOCTOU）**：两个并发登录步可同时通过判空导致双 spawn、句柄互相
  覆盖；现临界区内「取守卫 → 收尸 → 判空 → spawn → 登记」一锁到底
- **`tailscale login` 等待者并进共享退出链**：应用退出与升级安装两条路径都会收掉登录子进程
- **argv 红线守卫补强**：登录臂只能经由单飞槽发起（形态针测试堵住绕过逃逸路）
- **升级检查 IPC 契约修复**：enum 字段补 camelCase（此前前端读 `currentVersion` 恒 undefined，
  弹窗「当前版本」尾空）；下载中禁关弹窗（防误关只剩进度黑洞）
