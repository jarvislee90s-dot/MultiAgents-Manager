# 批次戊前置 · 远程端审批/问答全能力差距矩阵（四终端）

> 2026-09-22 · 依据：用户三轮手工测试（含本轮 19:56-20:02 codex 多题会话）+ 审计表 + rollout/wire/SQLite 对账 + 状态链代码勘察 + 官方文档调研。
> **目标定义（用户裁定）**：远程端能做到桌面端的所有交互——审批（含 N 选项对话框）、问答（单选/多选/多题）、自由作答（Type something/Other/notes）、模式与权限切换（含回显当前档）、计划展示。**用户在任何卡片状态下都不能被卡死**。
> 本文档 = 差距矩阵 + 新 bug 根因 + 批次戊任务输入。R2（composer 转向 claude / 多选形态裁决 / D20 稳定闸 / 文档项）按用户实测裁决收敛后另行收口。

## §4 终端文本采集能力（回答"能不能像 playwright 一样打印终端文本"）

**能，且已经建成**：批次丁已有的 `read_screen_window`（后端 Rust）与 `ConOut.ps1`（探测套件）就是终端可见窗口的**逐行文本打印**——独立复审探测的 91 项证据里每一步都附了屏读文本（如 `screen-r1v-after-down.txt` = 按下 ↓ 后的逐行原文）。

**从现在起的证据规范**（写进批次戊执行提示词）：所有探测/修复验证的每一步必须附「注入了什么键 → 屏读逐行原文」对照，不再只给截图；你只需要在行为怪异时告诉我们**大致时间点**，我们从审计表（每次注入的键/结果都有落账）+ 屏读重放直接定位，不需要你手抄终端内容。
