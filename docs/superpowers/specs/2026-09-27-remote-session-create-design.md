# 远程新建会话（session-create）设计 spec

> 日期：2026-09-27 · 状态：设计定稿（探测批次先行，编码批次待探测回传后另立计划）
> 背景动机：2026-09-25 手工实机验证了一次「主机开终端 → 起 claude → 注入首句 → 会话上板 → 移动端可收发」的完整链路（Test 目录实测，中文注入原文落盘无乱码）。本设计把这条链路产品化为移动端一键操作。
> 宪法裁决（用户 2026-09-26）：「远程新建会话」**提前为二期收尾功能**（MASTER-PLAN D 裁决 + F2.x 新条目，正文修订随编码批次执行）。三期红线「不暴露任意 shell」边界声明：仅限四家固定 CLI 命令（无参数拼接、无任意命令），目录受黑名单约束，不属于任意 shell 暴露。

## 1. 范围

四家终端 TUI 工具：claude / codex / kimi / opencode。zcode（APP 形态，M11 无头）与 dsh（web 宿主）不在本批。

平台：**Windows 先行**（全链实机交付）；macOS 后补（同构实现 + 编译门禁；弹窗处置档位由探测批次 M1 判定：锚点式 / 剧本式退化 / 本批不做）。

## 2. 用户流程（移动端）

首页看板右上「+ 新建会话」入口 → 表单三步：

1. **工具**：四选一；未安装 / 未启用的置灰并标原因（数据源 = 现有 enabledTools + 安装探测）。
2. **目录**：两种来源——
   - **候选列表**：`GET /create-projects?days=7`，项目 = 当前看板快照的 project_path ∪ session_archive 按 last_seen 过 7 天窗的 project_path，去重、按最近活跃排序、带工具集合。「7 天」是查询窗口（归档只增不删，与历史页同口径）。
   - **手填完整路径**：前端格式提示 + 服务端权威校验（语法合法；盘符/卷存在；不在系统危险目录黑名单——与文件读取黑名单同源策略；目录不存在则**递归创建**）。
   - 同项目同工具已有活跃会话 → **黄字提示**（服务端算好信号返回）：「该项目已有该工具的活跃会话，多实例下后续消息路由可能混淆（桌面域已实证配对交叉；远程投递将附加提示）」。
3. **首句**（可选）：默认固定探针 `hi`（四家会话文件均首条用户消息后才落盘，空回车不物化——探针是会话物化的必要条件）；用户可自填替换。

提交后**异步任务 + 进度态**：`校验 → 开终端 → 处置弹窗 → 注入首句 → 等待上板`；新会话卡物化后自动跳入会话页；总预算 90s（探测定案表回填精确值），超时回执**分阶段失败原因** + 可重试。

## 3. API

| 端点 | 方法 | 语义 |
|---|---|---|
| `/m/api/v1/create-projects?days=` | GET | 候选项目列表（只读，gate 下） |
| `/m/api/v1/session-create` | POST | `{tool, projectPath, firstMessage?}` → `{taskId}`；校验失败 400（带原因码）；同参数任务在飞 409 |
| `/m/api/v1/session-create/status` | GET | `{taskId}` → `{phase, detail?, sessionId?}`；phase ∈ validating / opening_terminal / dialog_handling / injecting_first / waiting_materialize / done / failed |

- **任务态为内存态，不持久化**：MAM 重启丢任务，手机端查不到（404）即引导重试。创建是一次性动作，不值得新表与迁移成本。
- **并发**：全局同时只允许 **1 个**创建任务在飞（进程发现与弹窗处置互斥语义）；重复提交 409。
- **审计**：`action=create`（成功 / 失败+阶段原因）；每次弹窗自动处置**逐条留痕**（锚点类型 + 所发按键）——「全自动 + 审计留痕」用户裁决（2026-09-26）的落点。

## 4. 创建管线（服务端状态机）

1. **校验**：工具在场；路径校验 + 黑名单 + 递归建目录；多实例黄字信号。
2. **起终端**：复用 resume 开窗机制（Windows：WT 优先 / conhost 兜底；macOS：Terminal.app 优先 + iTerm2 已知死窗规避 + 效果回查），命令 = **裸工具名**（形态由探测批次 P1 定案入命令表）。
3. **进程锚定**：起窗后按「目标目录 cwd + 新进程」发现 TUI 进程并记 pid；后续屏读 / 按键 / 注入全部锚定该 pid，不受同项目多实例干扰。
4. **弹窗处置（方案二，屏读锚点驱动）**：周期屏读（Windows CONOUT$ 屏读层，与注入共用既有互斥锁）→ 匹配**屏读锚点账本**（复用单一真源账本，新增「新建会话」场景槽位：信任框 / 更新提示 / 引导流 / 空闲输入框四类）→ 按类分派处置键；**见到空闲输入框锚才进入下一步**。连续 N 轮无命中 → 失败回执「检测到未识别界面，需人工到电脑前处理」+ 截图留档探测基座——诚实报错，不盲打。macOS 按探测档位退化。
5. **首句注入**：pid 锚定直调生产注入引擎（此时无会话 id，不走常规投递路径）；文本 = `{首句} [mobile 发起设备花名]`——设备身份在创建请求过闸时记录，服务端全程使用，**不依赖手机持续在线**。
6. **物化等待**：监看项目目录**新会话文件**出现（四家落点由探测 P4 定案）→ 首句戳命中确认 → 会话卡自然上板 → 回执 sessionId。
7. **失败语义**：各阶段失败原因独立回执 + 可重试标注；**失败不自动清场**（已开终端窗口保留供用户查看现场，回执说明）。
8. **附带行为**：codex 新建成功后若 hooks 信任门未开，回执附带既有「信号健康度」提示（复用现有引导），不自动处理。

## 5. 配对不确定门扩展（附带修复项）

发现层暴露「同工具同项目 ≥2 进程」的配对不确定状态到会话数据；远程投递命中该态时回执**附加提示字段（不拦截）**；新建表单黄字复用同一信号。依据：桌面跳转域第四轮实机验收 3c 实证 codex 同项目双开两次静默锁错（issue #48 系），根因是发现层 pid 位置配对可交叉；远程注入路径共享同一 pid 产物且现无守卫（用户裁决 2026-09-27：门装上、提示不拦截）。

## 6. 批次结构

- **Phase P 探测批次（先行，独立执行计划）**：`docs/superpowers/plans/2026-09-27-remote-session-create-probe.md`。产出五类定案：① 四家裸命令表；② 弹窗锚点文案 + 处置键序；③ 冷启动/物化时延（超时预算定值）；④ 首句物化落点；⑤ macOS 通道档位。
- **Phase C 编码批次（探测回传后另立计划）**：宪法 D 裁决落正文 → 锚点账本场景扩展 → 创建状态机 → API + 审计 → 移动端 UI → 配对门扩展 → 门禁 + 实机验收。

## 7. 验收

- 人工（C 段）：四家新建全链（含信任框路径）；更新提示路径；未识别界面报错路径；多实例黄字；路径边界（黑名单命中 / 盘不存在 / 深层创建）；审计逐条可查（create + 弹窗处置留痕）。
- 自动化：`#[ignore]` 实机 E2E（新建 → 物化 → 戳命中全链，复用 m9r_e2e 模式）。

## 8. 不做清单

任意命令/参数（宪法红线）；macOS 锚点式（除非探测 M1 证实可达）；任务持久化表；自动信任 codex hooks 门；同项目多实例的注入隔离（只提示不拦截，按裁决）。
